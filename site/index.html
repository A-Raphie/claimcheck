How it works

You bring the change and the claims. It brings the proof.

STEP 1 · YOU PASTE THE CLAIMS

Say what you were told

Claims come from anywhere: the agent's PR description, the ticket it was supposed to close, the release notes, or your own suspicions. One claim per line.

"all tests pass" "no new dependencies were added"
STEP 2 · CLAIMCHECK RUNS THE CHECKS

It checks them for real

It copies your repository into a sandbox, runs the actual test suite, reads the actual files, and searches the actual code. Nothing is taken on faith.

run_tests -> "# pass 2 / # fail 1" search "fetchUser" -> still exported
STEP 3 · YOU GET VERDICTS WITH RECEIPTS

True, false, or nobody could check

Each claim gets VERIFIED, REFUTED, or UNVERIFIABLE, with the exact output that decided it. Undecidable claims say what would settle them. It never guesses.

REFUTED · "tests pass": 1 test failed UNVERIFIABLE · "2x faster": add a benchmark

Questions
What does UNVERIFIABLE mean?+

Some claims cannot be decided from a repository: "twice as fast", "more readable", "cuts memory by 30 percent". Claimcheck refuses to guess and marks them UNVERIFIABLE. A verdict that cannot be backed by evidence is treated as a bug, not a disclaimer.

Which models does it use?+

Any OpenAI-compatible endpoint: OpenAI, Groq's free tier, OpenRouter, local servers. Model and pricing are one environment variable each. The executor itself is deterministic TypeScript with no runtime dependencies.

What does a run cost?+

Each claim costs a handful of small model calls (a plan, then a judgment per claim). The live report shows the exact figure for every run; the reported sample run came in under half a cent. The mock mode costs nothing.

How is this reproducible?+

The 13-case benchmark (28 claims with planted ground truth) is regenerated deterministically by one script. Every reported number traces to committed artifacts under eval-results/, and the mock path needs no key at all.
